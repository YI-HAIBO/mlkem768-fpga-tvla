## 二、本轮新增实证（#6 二阶检测）

**模型**：异方差纯二阶泄漏 P = C + N(0, σ²(1+β·HW(V)))，β=1.0，K_fixed=0xFF（HW=8），σ=3，n=4096，8-bit 量化。
**结果**（`verify/analyze_second_order.py` → `results/second_order_analysis.json`）：

| 场景 | 一阶 t | 一阶判 | 二阶 t | 二阶判 | var_f / var_r |
|---|---|---|---|---|---|
| S1 一阶泄漏 a=0.30 | +19.01 | ✅ | +0.77 | — | 9.4 / 9.2 |
| **S2 纯二阶 β=1.0** | **+1.11** | ❌ 漏掉 | **+18.30** | ✅ 抓到 | **83.8 / 45.0** |
| S4 无泄漏 | +1.39 | — | +1.43 | — | 9.4 / 9.0 |

**判定**：`extension_effective=True`——现有板上监控器（一阶）**会漏掉纯二阶泄漏**，而**中心二阶矩 Welch t 能抓到**（方差 83.8 vs 45.0 显著不同）。这证明论文 L226-228"cannot detect higher-order leakage"局限有**已验证的可落地解**：在整数引擎增加中心二阶矩统计即可。

## 三、本轮新增实证（#8 攻击视角）

**模型**：P = C + a·HW(K⊕D) + N(0,σ²)，σ=3，CPA 向量化（HW 查表），REPS=15。
**结果**（`verify/attack_sr_vs_traces.py` → `results/attack_sr_vs_traces.json`，SR=top-1 成功率）：

| 迹数 | protected (a=0) | monitor 阈值 (a=0.08) | unprotected (a=0.30) |
|---|---|---|---|
| 1024 | 0.07 | 0.07 | 0.27 |
| 2048 | 0.00 | 0.00 | 0.33 |
| 4096 | 0.00 | **0.27** | 0.60 |
| 8192 | 0.07 | 0.13 | 0.60 |
| 16384 | 0.00 | 0.27 | 0.53 |
| 65536 | 0.00 | **0.67** | 0.67 |

**判定（全部 True）**：protected 抑制到噪声地板；**监测窗口 4096 迹时攻击成功率 0.27 < 0.50（攻击者无法过半恢复）**；16×迹数 SR 升至 0.67（灵敏度差距保留）。这直接回应"监控器是否阻止现实攻击"：在板上监控器触发检测点（a=0.08），攻击者在 4096 迹窗口**不能**以>50% 概率恢复密钥，需 16× 迹数且仍仅 67%。
**诚实说明**：单字节 HW 模型存在**密钥混叠**（相差数 bit 的密钥预测高度相关），SR 天花板低于 1.0，故量化主张是"对照"（protected≈0 vs 监测窗口<0.5 vs 16×上升），而非绝对成功率。

## 四、本轮新增管线（#7 NIST SP 800-90B）

**实现**：`verify/entropy_90b_estimators.py`（MCV / Collision / Markov / Shannon），跑在仿真原始熵流（10 Mbit，`trng_long_100mbit.bin`）。
**结果**（`results/entropy_90b_estimates.json`）：

| 估计器 | bits/bit | 说明 |
|---|---|---|
| MCV | 0.9994 | 接近平衡（P(1)=0.5002） |
| Collision | 1.0000 | IID 参考 |
| **Markov** | **0.5422** | **非 IID 有效值**（p01,p10≈0.687 > p00,p11≈0.313） |
| Shannon | 1.0000 | IID 参考 |

**发现**：原始 RO 流呈**强交替结构**（转移概率 0.687 vs 0.313），真实非 IID min-entropy ≈0.54 bits/bit，**低于**论文 jitter 模型理论值 0.909——原始源存在时序相关，正因如此需 SP800-90B 调理（调理后 13/14 通过 SP800-22，Random Excursions 为固有属性）。
**管线就绪**：真实板级熵源采集数据可直接喂入同一管线（`pipeline_ready_for_silicon=True`）。

## 六、本轮新增（#9 聚合基准 + #10 权衡）

**#9 基准**（来自既有报告/日志，聚合口径）：

| 量 | 值 | 来源 |
|---|---|---|
| 完整密钥建立路径（KeyGen+Encaps+Decaps+熵源+自检） | 352,627 周期 @100 MHz = 3.526 ms | `board_top_sim_clkdiv1_1108.log` |
| KEM 单操作延迟（论文表） | 0.032 ms | 论文 Tab.5 |
| 面积-时间积 / 每 LUT 吞吐 | 1.06×10³ | 论文 Tab.5 |
| 监控器开销 | 601 LUT / 429 reg / 8 DSP（≈1.8% / 1.1%） | 论文 §VI |

> **每操作（KeyGen/Encaps/Decaps）独立周期数**：既有材料为聚合口径（板级 POST 整链、KAT 向量数），独立分解需定向 RTL 仿真（加每相周期计数器），列为后续项（低成本，仿真已可跑）。

**#10 灵敏度-位宽权衡**（`d_min·σ_pooled`=0.02067 native HW；量化地板=6/(2^W−1)）：

| 代理位宽 W | 量化地板 (native) | 可检测下限 (native) | 限制因素 |
|---|---|---|---|
| 6（本设计） | 0.0952 | 0.0952 | 量化 |
| 8 | 0.0235 | 0.0235 | 量化 |
| **9** | 0.0117 | **0.0207** | **统计功效（交叉点）** |
| 10+ | 0.0059 | 0.0207 | 统计功效 |

→ **加宽代理到 ~9 bit 后收益递减**（统计功效成为限制）；Artix-7 DSP48E1 限宽 ~6 bit（量化受限），宽 DSP 器件（如 UltraScale+）可到 8-9 bit 达交叉点。这同时支撑 #2 灵敏度归因与 #10 器件迁移论证。

## 七、本轮确认（#10 RTL 已参数化）

**`rtl/real/tvla_online.v`** 已参数化：`parameter SAMPLE_W=6`（代理位宽）、`parameter N_LOG2=12`（n=2^12=4096），注释明确"64-bit 评估路径对 N_LOG2≤14 成立"。→ **#10A（参数化）已在 RTL 满足**。
